Hardware and infrastructure roadmap

This separates what exists today from what could be added. Nothing in the proposed column is built. Specifications are given only where a measurement or simple arithmetic supports them.

Built Today

  • The whole simulation runs in the user's own browser. There is no server, database or account.
  • Measured in Node on a 4-core, 16 GB laptop: one 10-year plan simulation (87,600 hours) takes about 0.26 to 0.89 s (median 0.42 s).
  • One run holds 41 hourly data series, about 24 MB of memory. The Prototype keeps recent runs cached.
  • Measured in headless Chrome: about 205 MB of JavaScript memory after load, rising to 350 to 600 MB after exploring several projects.
  • The 384-plan library was pre-computed offline, so opening the app does not re-run it.

Proposed Where limits will appear

  • Many scenarios at once, or many years of weather, will outgrow one browser tab: 384 runs would take about 2.7 minutes on one core (384 × 0.42 s).
  • Portfolio and enterprise use needs shared, saved projects, which need a server.
  • Real-time monitoring needs data from physical equipment, which the Prototype cannot receive.

Phased priorities

  1. Phase 1Hosted foundation. Accounts, saved projects and a hosted copy of the Prototype. Needs cloud storage and authentication, no special hardware.
  2. Phase 2Scale the simulation. A simulation API and job queue so batches run in parallel on cloud CPUs. Profile first, then size.
  3. Phase 3Customer data in. Upload and validation of customer meter and cost files (read-only), so projects use real numbers. This reuses the same cloud pieces.
  4. Phase 4Pilot-site telemetry. Sensors and one edge gateway at a willing pilot site, feeding a time-series store.
  5. Phase 5Digital twin. Calibrate the model to measured data and add monitoring and alerts.

Order reflects dependencies and cost: each phase uses what the previous one built, and hardware is deferred until a pilot partner exists.
