Transparent by design

Method & assumptions

This page describes the calculations in the current backend iteration. It should be updated with the code as the model expands.

1. Inputs and hard requirements

The engine uses the official packet timeline, seven-resource catalog, case settings, response parameters, prices, and stress windows. Initial service month must be 14–109, full demand is derived as service month + 10, and grid delay is a nonnegative integer. Resource blocks, maxima, availability dates, shared grid imports, and the 8-acre onsite limit are validated by the unchanged packet checker.

2. Portfolio selection

Iteration 1 checks a curated set of 14 capacity combinations: gas turbine, gas engine, fuel cell, selected wind and solar contract sizes, and one nuclear alternative. It picks the lowest total decision cost or lowest combined operational CO₂ among feasible candidates, depending on the selected preference. This is a limited search; it is not a proof of a global optimum. Batteries are not included in this candidate set yet.

3. Hourly dispatch

For each candidate the engine uses all 87,600 hourly intervals. Wind, solar, and nuclear deliveries share the import limit with merchant purchases. Onsite gas capacity can serve demand locally. The dispatch uses clean contracts first, then a transparent merit rule for gas and grid imports. Tier 0 remains local. Relocation and interruption are limited to designated stress hours and packet quantities.

  • No relocation or interruption: all customer load remains local.
  • Relocation allowed: Tier 1 may move to remote capacity; Tier 2 stays served locally.
  • Relocation and interruption: Tier 1 moves first; Tier 2 is interrupted only when needed.

Battery charging, cycling, and SOC optimization are deferred because the first candidate set does not select batteries.

4. Cost and environmental accounting

Official horizon, annual, cost, emissions, and physical metrics come from the packet’s checker. Costs include annualized capacity charges, available-generation contract payments, gas fuel and variable O&M, merchant purchases, relocation costs, and interruption consequences. Contract payments apply to available generation whether used or curtailed. Relocated energy includes remote electricity use and emissions; interrupted energy is shown separately.

Decision cost is not NPV. Emissions use the packet’s screening factors. Clean share is not hourly clean coverage.

5. Validation, limitations, and reproducibility

The default month-20, zero-delay export is checked with the unchanged starter/check_submission.py. The result reports 87,600 hours. Each displayed recommendation includes the candidate count and validation status. Limited candidate search, no battery selection, simplified dispatch, and omitted unit commitment, startups, outages, and gas-delivery limits are current limitations.

Run from the extracted packet folder with python team_app/run.py --start-month 20 --grid-delay-months 0 --policy strict --objective cost --compare-policies. Start the local dashboard with python team_app/server.py. It binds to loopback by default and makes no external API calls.
